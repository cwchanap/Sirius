# HPA-384 Save/Load Responsive Cards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the runtime-built `SaveLoadDialog` with a scene-authored, responsive Sirius Save/Load card screen while preserving the current SaveManager, Main Menu, Pause, load-handoff, backup-recovery, input-lifecycle, and scene-transition behavior.

**Architecture:** Add one `SaveLoadScreen.tscn` + `SaveLoadScreenController` vertical slice. `SaveManager` gains only an explicit metadata `SaveSlotState` so the UI can distinguish corrupted from newer-version saves. Main Menu and Game keep their explicit `UIScreenHost` integrations and domain handlers; they only swap the concrete view. Save/Load locally caps the existing shell panel's Y size so the shell `BodyScroll` owns compact overflow. No save facade, reusable card component, host factory, navigation service, or shared confirmation framework is introduced.

**Tech Stack:** Godot 4.6.2, C#/.NET 8, GdUnit4, existing Sirius Theme / `SiriusModalShell` / `UIScreenHost`.

**Design:** `docs/superpowers/specs/2026-08-11-hpa-384-save-load-design.md`

## Global Constraints

- Preserve three manual slots (0–2) and autosave (3); do not add slots.
- Preserve `SaveManager` ownership of file I/O, full load, version validation, atomic writes, and backup restoration.
- Preserve `Game` ownership of gameplay save eligibility and `CollectSaveData`.
- Preserve Main Menu/Game ownership of `PendingLoadData` and scene transitions.
- Leave `SaveSlotInfo.Exists` / `IsCorrupted` semantics unchanged for Main Menu Continue.
- Do not expose Delete, playtime, thumbnails, renaming, cloud saves, auto-repair, or fabricated metadata.
- Reuse Sirius Theme, `SiriusModalShell`, `SiriusUiMetrics`, and existing local `UIScreenHost`s without adding shared APIs.
- Overwrite confirmation remains feature-local; HPA-572 still owns the future shared confirmation/error path.
- Save/Load uses shell `BodyScroll` as its only vertical overflow owner; Settings' page-local scroll ownership is not copied.

private bool CanActivateSlot(int slot, SaveSlotInfo info)

    if (!_saveManagerAvailable || _terminalEmitted || HasActiveChildDialog)

- [ ] **Step 6: Implement the concrete shell-scroll height bound**

`SiriusModalShell` owns width only, so Save/Load must cap its nested panel locally. Use `-1f` for uncapped X; `0` would be an actual zero-width maximum in Godot 4.6.

```csharp
private void RefreshLayout()
{
    var size = GetViewportRect().Size;
    var compact = SiriusUiMetrics.IsCompact(size);
    var margin = SiriusUiMetrics.SafeMargin(compact);
    var maximumPanelHeight = Mathf.Max(0f, size.Y - margin * 2f);

    _shell.Compact = compact;
    _shell.RefreshPresentation(size);
    _shellPanel.CustomMaximumSize = new Vector2(-1f, maximumPanelHeight);
    _shellBodyScroll.FollowFocus = true;
    _cardsGrid.Columns = compact ? 1 : 2;

    ApplyCardTypography(compact);
    ApplyMinimumTargets(compact);
}
```
