# Sirius Godot E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an independently runnable Godot E2E test project and GitHub Actions workflow that launch Sirius as a real child process and cover menu navigation, an Orc battle lifecycle, and a health-potion shop purchase.

**Architecture:** Vendor only the pinned C# automation runtime from `cwchanap/godot-e2e`; keep the client/testhost outside the game project and communicate only through its authenticated loopback protocol. Add one small test-only raw-protocol helper for selectors and `Vector2i`, then express each gameplay flow against existing production nodes, methods, signals, and UI controls. The E2E workflow duplicates only the Godot setup needed to run this lane; the existing GdUnit4 workflow stays unchanged.

**Tech Stack:** Godot .NET 4.6.2, .NET 8, GdUnit4 5, vendored `cwchanap/godot-e2e` at `6f251e864e195aa54345475f21ca38b6dc4c0e6c`, GitHub Actions, Xvfb.

**Spec:** `docs/superpowers/specs/2026-08-30-godot-e2e-design.md`

## Global constraints

- Keep `Sirius.sln` and `.github/workflows/tests.yml` unchanged. The E2E project is intentionally not part of the solution.
- Vendor only `addons/gdunit_e2e/{csharp,protocol,runtime,server}` plus the upstream `LICENSE` and `NOTICE`; exclude upstream `client/` and `gdunit/`.
- Do not add production-only E2E APIs, nodes, autoloads, selectors, input routes, or test data. Test the current scene graph and public `GridMap` API.
- Every `[TestCase]` calls `E2EGame.RunAsync` directly, starts a fresh non-headless child, and has no retry or shared state. Do not wrap `RunAsync`, so its caller-derived failure-artifact path stays useful.
- Use `E2ELaunchOptions.Timeout = TimeSpan.FromSeconds(30)` only for the child handshake. Every raw server wait must pass a matching server timeout and a transport timeout one second longer.
- Use `E2EGame.ClickNodeAsync` for controls and `CallMethodAsync<string>` for `get_meta("ItemId")`. Use raw `SendCommandAsync` only for selectors/waits and `Vector2i` property or method values, which the pinned C# client does not deserialize. A one-use test-local `wait_process_frames` loop is allowed solely to observe battle-screen teardown.
- Treat every false pre-target movement step as a layout regression. Keep the approved literal FloorGF routes; do not add pathfinding or a test route planner.
- The E2E CI lane must run Debug Sirius output with the real Godot executable under Xvfb. It must not use `test.runsettings`, the existing headless wrapper, coverage, the GdUnit4 addon download, a unit-suite invocation, or a Windows matrix.

  internal static Task<IReadOnlyList<string>> FindNodesAsync(
      E2EGame game, string by, string value, string? type = null, string startPath = "/root");
